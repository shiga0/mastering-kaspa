# はじめに

## 本書について

『Mastering Kaspa』は、Kaspaの基礎からBlockDAGとコンセンサス、トランザクション、マイニング、ノードの内部構造、アプリケーション開発までを学ぶために公開している、執筆中の技術書です。

本書では、仕組みの説明を、設計上の理由・ソースコード・検証結果につなげて読み進めます。目指すのは、**なぜその仕組みが必要で、実装では何を確かめればよいかを、自分で説明できるようになること**です。

## なぜKaspaなのか

Bitcoinの[原論文](https://bitcoin.org/bitcoin.pdf)は、Proof of Work（PoW）とP2Pネットワークによってトランザクションの履歴を合意する仕組みを提案しました。

ブロックの伝播に要する時間に対して生成間隔を短くすると、ノードが異なる先端を見ながら採掘する機会が増えます。並行して生成されたブロックをどう扱うかは、安全性と処理能力を考えるうえで重要な問いです。この問題とGHOSTDAGの設計の背景は、[PHANTOM / GHOSTDAG論文の概要](https://eprint.iacr.org/2018/104)でも説明されています。

本書の基準版で扱うKaspaは、複数の親を参照できるBlockDAGと、GHOSTDAGによる親選択・ブロックの分類を用います。Bitcoinとの比較を通じて、この構造が何を可能にし、どのような条件や制約を持つのかを学びます。実装の具体的な規則は、[基準版のGHOSTDAG実装](https://github.com/kaspanet/rusty-kaspa/blob/fcd9c28f9b211b9872a0c90a8c94f79466ffb063/consensus/src/processes/ghostdag/protocol.rs)と各章の照合記録に結びつけます。

## 本書で目指すこと

読み終えたテーマについて、次のことができるようになることを目指します。

- BitcoinとKaspaの構造を比較し、BlockDAG・GHOSTDAG・PoWの役割を説明する。
- ブロックの受信・検証・コンセンサス処理と、トランザクションやUTXOへの反映を区別する。
- ノードの実装やRPCを読み、教育用モデルと実際の処理の対応・省略を説明する。
- 教材やDevnet実習を実行し、入力・期待値・観測結果・限界を記録する。
- 論文・Kaspa Improvement Proposal（KIP）・固定したソースコードから、説明の根拠をたどる。

## 想定読者と前提知識

ブロックチェーンの内部構造に関心があるエンジニアや、Kaspaを調査・開発に利用したい読者を想定しています。前半では、トランザクション・PoW・P2P・DAGなどの用語から説明します。

実装編では、プログラミングの基礎、Rustの基本文法、ターミナル操作、ネットワークの基礎知識を使います。実習によってはPythonやNode.jsも必要です。必要なツールと動作確認環境は[本書の対象バージョン](baseline.md)、準備手順は[付録A](appendices/appendix-a.md)と各実習を確認してください。

## 本書の読み方

初めて読む場合は、目次の上から進めてください。このページの次に[本書の対象バージョン](baseline.md)で基準を確認し、[技術レビューの進捗](review-status.md)で確認済みの範囲を把握します。[エコシステムマップ](ecosystem-map.md)で全体像をつかんだら、[第1章](part-01-foundations/chapter-01.md)から基礎を学びます。

各部の役割は次のとおりです。

| 部 | 主に学ぶこと |
|---|---|
| Part I：第1〜8章 | Bitcoin・暗号技術・分散システムからBlockDAGへ進むための基礎 |
| Part II：第9〜14章 | ノードの構造、ブロック検証、GHOSTDAG、難易度調整、Virtual State |
| Part III：第15〜20章 | トランザクション・署名・Mempool・採掘・セキュリティ |
| Part IV：第21〜28章 | ストレージ・同期、RPC・SDK・ウォレット、実装の読み方とDevnet実習 |
| Part V：第29〜34章とArgent補足 | 研究、KIP、スクリプティング、言語、L2などの発展的な話題 |
| Part VI：第35〜36章 | アプリケーションの設計と開発への参加 |

各テーマは、原則として **概念 → 問題 → 原理 → 設計 → 実装 → 検証** の順で解説します。途中で知らない用語が出てきたら[付録Bの用語集](appendices/appendix-b.md)を参照してください。

### 用語とサンプルの扱い

本文では、transactionの訳語を「トランザクション」、GHOSTDAGの分類を `blue`・`red` と表記します。コードの識別子、引用、原資料の名称は元の表記を使います。「はじめに」と読者向けの案内は「です・ます」、技術解説は「である」を基本とします。

サンプルには、概念を確かめる教育用モデル、説明の一部を示すコード・擬似コード、実ノードで動かす実習があります。コードを実行するときは、各章に記載した前提・依存関係・実行手順・省略した機能を確認してください。教育用モデルのテスト成功だけで、Kaspaとの互換性や実ノードでの動作が確認できるわけではありません。

実ノードの実習には、実験用ネットワークであるDevnetを使います。[第28章](part-04-development/chapter-28.md)の手順と検証範囲を確認し、実験用の鍵やデータを実資産の管理から分けて扱ってください。

## 対象バージョンと執筆状況

本書の実装照合は `rusty-kaspa` v1.0.1を基準にしています。現在のMainnetや最新リリースとの一致を示すものではありません。ネットワーク、SDK、ツールの版と確認範囲は[本書の対象バージョン](baseline.md)にまとめています。

研究・提案・開発中の機能を扱う章では、論文やKIPの説明、公開実装の存在、ネットワークでの有効化を区別して読み進めてください。

原稿には、未レビューの説明や実行確認前のコードが含まれています。個別のソース照合、教材のテスト成功、章全体のレビュー完了はそれぞれ別の状態です。確認できた範囲は[技術レビューの進捗](review-status.md)と各検証記録を参照してください。

誤りや説明の不足を見つけた場合は、GitHubのIssueやPull Requestで、該当箇所と確認した根拠を知らせていただけると幸いです。
