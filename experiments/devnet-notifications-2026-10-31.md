# Devnet：実通知・欠落の補完・SQLiteの永続記録

実施日：2026-10-31。ノード・SDK・アーカイブSHA-256は送金実習と同じ。Python 3.11 / websockets 14.1、標準sqlite3、Node.js 20.0.0で実行。

## 実行

```bash
KASPA_SDK_ROOT=<展開したSDKのルート> python3 experiments/devnet/notifications.py
python3 -m unittest discover -s experiments/devnet -p 'test_*.py'
```

`watch-once.cjs` は公式SDKの `subscribeUtxosChanged` で実通知を1件受け取り、公開Outpointと金額に正規化して監督プロセスへ渡す。通知元に秘密鍵は不要。監督プロセスは標準SQLiteでOutpointに一意制約を設け、同じ通知を意図的に2回適用する。

購読プロセス終了後も採掘し、通知を受信しなかった変更を作る。DBの接続を閉じ、別プロセスで同じDBを開いて既存記録を確認。その後、採掘を停止した状態でRPCの完全な照会結果を取得し、SQLiteの観測状態を1トランザクションで置き換える。同じスナップショットの再適用でも結果が変わらないことを確認する。

DBは一時ディレクトリだけに作り、実験終了時に削除する。公開JSONには件数・合計金額・試験結果だけを収録する。生通知、DB、内部パスは公開しない。`.gitignore` にSQLite本体とWAL等の除外も追加した。

SQLite単体テストは4件成功：追加/削除の重複、矛盾する金額でバッチ全体をロールバック、スナップショットから消えた出力の無効化、補完処理失敗時のロールバックと再読込。

## 実装上の修正

手書きの共通API名をwRPCへ送っても購読できなかったため、公式SDKの購読を利用した。最初はSDK通知のエントリ形式とRPCスナップショット形式の違いで失敗。Outpointとamountを同じ形へ正規化して解消した。これら途中の失敗はPASSに含めない。

## 限界

これは単一アドレス、単一書き込み主体の現在UTXO観測ストアであり、決済履歴の累積売上・成熟残高・送金可能額を表すものではない。Coinbaseの成熟や手数料は観測合計から判断しない。スナップショットで消えた出力を無効化しても、その理由が支出・再編成・その他のどれかは判別しない。

実ネットワークで通知を2回配信したのではなく、受信した実通知をアプリ側で2回適用した試験。採掘停止後に照会しており、稼働中のスナップショットと通知の競合・順序逆転、再購読後のバッファの扱いは未検証。古い通知を後から適用すると状態を戻す可能性があるため、この教材をそのまま本番に使わない。

複数ワーカーの競合、永続DBへの実際のプロセスクラッシュ、reorgイベントと会計上の取り消し、全UTXO集合の検証は未実施。4件の単体テストで削除や失敗時の原子性は確認したが、今回は実ノードのremoved通知自体は0件である。
